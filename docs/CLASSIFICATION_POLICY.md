# سياسة ومنهجية التصنيف (Classification Policy & Methodology)

كل عنصر أمني يُستورد من `Raw_Catalogs` يجب أن يُصنَّف بصرامة وفق نموذجي **USACM v2.2.1** و **SDT v2.2.1** قبل نشره في الكتالوج المرجعي. هذه الوثيقة تحدد المنهجية والمعايير والقواعد لتصنيف **كل عنصر على حدة**.

## 0. ترتيب خطوات التصنيف (Pipeline لكل عنصر)
لكل سجل خام في `raw_artifacts`، طبّق الخطوات بالترتيب، وسجّل كل قرار مع تبريره:

1. تحديد **النوع** `type` (ART-*).
2. تحديد **مستوى التجريد** `abstraction_level` (ABS-*).
3. تحديد **المجال الرئيسي والفرعي** `primary_domain` + `sub_domain` (SDT).
4. تحديد مصدر الإلزام ومستواه `source` (SRC-*) و`obligation_level` (OBL-*)، و`granularity_level` (GRN-*).
5. للأنواع الخاصة: `requirement_type` (لـ ART-REQ)، وحقول الضبط `control_nature`/`control_function`/`testability` (لـ ART-CTR/ART-CTE)، و`asset_type`/`asset_criticality` (لـ ART-AST).
6. صياغة المحتوى وفق [`AUTHORING_POLICY.md`](AUTHORING_POLICY.md) (تعريف مختصر/مطول، هدف، نطاق، تحقق، أدلة).
7. استخراج **الوسوم** المطبّعة (سياق ثانوي فقط).
8. إنشاء **الربط بالأطر** (`framework_mappings`) و**العلاقات** (`artifact_relationships`).
9. حساب **الثقة** وتوجيه المنخفض منها للمراجعة البشرية.
10. **التحقق** من القيود ثم **النشر**.

القاعدة الفاصلة: **النوع، المستوى، والمجال حقول مستقلة** — لا يُشتق أحدها آلياً من الآخر بلا قاعدة صريحة وتحقق (AGENTS.md قاعدة 3).

## 1. اختيار النوع (`type` — ART)
النوع يجيب عن سؤال: **"ما هذا العنصر؟"**. لا تُعامل كل العناصر كضوابط.

| اختر | عندما يكون العنصر | مثال |
|---|---|---|
| `ART-REQ` | متطلباً/نتيجة أمنية دون فرض طريقة تنفيذ | "يجب جرد كل الأصول" |
| `ART-OBJ` | هدفاً أمنياً عاماً | "ضمان خصوصية البيانات" |
| `ART-PRI` | مبدأً حاكماً | "أقل صلاحية" |
| `ART-POL` / `ART-STD` | سياسة إدارية معتمدة / معياراً | سياسة MFA / معيار تشفير |
| `ART-CTR` | إجراءً أو آلية تقلل خطراً | "جدار ناري" |
| `ART-CTE` | تحسيناً على ضابط قائم | إضافة MFA لضابط دخول |
| `ART-PRO` / `ART-PRC` / `ART-PLN` / `ART-TSK` | عملية / إجراء تشغيلي / خطة / مهمة | إجراء الاستجابة للحوادث |
| `ART-CFG` | إعداداً تقنياً محدداً قابلاً للفحص | "تعطيل SSH root login" |
| `ART-RUL` | قاعدة أداة فنية | قاعدة WAF |
| `ART-EVD` | دليلاً يثبت التطبيق | تقرير، سجل، شهادة |
| `ART-MET` | مقياساً/مؤشراً | نسبة الأصول المجرودة |
| `ART-EXC` | استثناءً أمنياً | استثناء مؤقت من التشفير |
| `ART-RSK`/`ART-THR`/`ART-VUL`/`ART-AST` | العنصر نفسه خطر/تهديد/ثغرة/أصل | CVE، تهديد تصيّد، أصل خادم |
| `ART-OWN` | مالكاً/دوراً مسؤولاً | CISO |

قواعد التمييز الحرجة:
- استخدم `ART-CFG` للقيم التقنية والـ hardening، لا `ART-CTR`.
- استخدم `ART-REQ` للنتيجة المطلوبة، و`ART-CTR` لآلية تحقيقها.
- استخدم `ART-RSK/THR/VUL/AST` فقط إذا كان العنصر **نفسه** خطراً/تهديداً/ثغرة/أصلاً، لا ضابطاً يعالجها.

## 2. مستوى التجريد (`abstraction_level` — ABS)
يجيب عن: **"أين يقع العنصر في نموذج التشغيل؟"** — مستقل عن النوع.
`ABS-GOV` حوكمة · `ABS-RIS` مخاطر · `ABS-POL` سياسات · `ABS-CTR` ضوابط · `ABS-PRO` إجراءات · `ABS-TEC` تقني · `ABS-EVM` أدلة/قياس.

## 3. المجال الرئيسي والفرعي (SDT — مجال واحد فقط)
القاعدة: لكل عنصر **مجال رئيسي واحد ومجال فرعي واحد** ينتمي إليه حصراً (`sub_domain` يبدأ بكود `primary_domain`). الوسوم لا تحل محل التصنيف المجالي.

الثمانية الرئيسية: SD-01 حوكمة/مخاطر/امتثال · SD-02 أصول/بيانات/خصوصية · SD-03 هوية/وصول/امتياز · SD-04 بنية/شبكة/سحابة · SD-05 تطبيقات/تطوير/تغيير · SD-06 كشف/مراقبة/ثغرات · SD-07 استجابة/تعافٍ/صمود · SD-08 أشخاص/أطراف ثالثة/مادي. (40 مجالاً فرعياً، راجع SDT §5.1.)

### قواعد الترجيح (Tie-Breakers) عند التداخل
- **هوية سحابية (Cloud IAM):** إن كان التركيز على الهوية/المصادقة/التخويل/الامتياز → **SD-03**.
- **إعداد منصة سحابية أو حماية أحمال العمل** → **SD-04**.
- **اختبار تطبيقات/واجهات API** → **SD-05**.
- **اختبار اختراق واسع / Red Teaming / تقييم نضج** → **SD-06**.
- **ضوابط تقنية قديمة غامضة (Legacy):** إن لم تتجاوز الثقة 0.70 → **مراجعة بشرية إلزامية**.
- تلميح من المصدر: تصنيف NCA (domain/subdomain)، ووظيفة NIST CSF (GV/ID/PR/DE/RS/RC)، وموضوع ISO، وتكتيك MITRE — تُستخرج من `context_paragraph` وتُستخدم كمرشد لا كقرار نهائي.

## 4. الإلزام والتفصيل
- `source` (مصدر الإلزام): تنظيمي/قانوني/تعاقدي/معياري/داخلي/أفضل ممارسة/مبني على مخاطر.
- `obligation_level`: `OBL-MND` إلزامي · `OBL-CON` مشروط · `OBL-REC` موصى · `OBL-OPT` اختياري.
- `granularity_level`: من `GRN-HIGH` (عالي المستوى) إلى `GRN-EXECUTABLE`/`GRN-TECHNICAL` (قابل للتنفيذ/تقني).

## 5. الحقول الإلزامية حسب النوع (تفرضها قيود قاعدة البيانات)
- `ART-REQ` → `requirement_type` (RQT-*) إلزامي، وممنوع لغير المتطلبات.
- `ART-CTR` / `ART-CTE` → `control_nature` (NAT-*) و`control_function` (FUN-*) و`testability` (TST-*) الثلاثة إلزامية.
- `ART-AST` → `asset_type` و`asset_criticality` إلزاميان.
- `ART-EXC` → تاريخا الاعتماد والانتهاء إلزاميان.
- `ART-POL`/`ART-STD`/`ART-PRC` المنشورة → `effective_date` إلزامي.

## 6. الوسوم (سياق ثانوي فقط)
استخدم الأنواع السبعة فقط (Technology, Framework, Concept, Context, Threat, Data, Party) وخزّنها مطبّعة في `artifact_tags`. الوسوم **لا** تُستخدم بديلاً عن التصنيف المجالي (SDT).

## 7. قابلية الاختبار (`testability` — TST)
`TST-AUTO` (فحص آلي، مثل إعدادات Linux) · `TST-MAN` (مراجعة بشرية) · `TST-DOC` (مستندي) · `TST-INT` (مقابلة) · `TST-NA`.

## 8. الثقة والمساءلة والمراجعة البشرية
- كل تصنيف آلي يجب أن يتضمن: `classification_confidence` و`classification_rationale` و`ai_review_status` و`requires_human_review`، والبدائل المرفوضة عند وجودها.
- **إن كانت `classification_confidence ≤ 0.70`:** اضبط `requires_human_review = 1` و`ai_review_status = AIR-HUMAN-REVIEW`، ويُمنع النشر التلقائي (قيد قاعدة بيانات صريح).
- قيم `ai_review_status`: `AIR-AUTO-ACCEPTED`, `AIR-HUMAN-REVIEW`, `AIR-HUMAN-APPROVED`, `AIR-HUMAN-REJECTED`.

## 9. الربط والعلاقات
- استخدم `framework_mappings` لربط العنصر بالأطر مع تحديد `mapping_strength`؛ وأي ربط غير `DIRECT` يتطلب `rationale`.
- استخدم `artifact_relationships` (12 نوع REL-*) بدل النص الحر؛ راجع [`RELATIONSHIP_POLICY.md`](RELATIONSHIP_POLICY.md). `REL-CNF` يتطلب `resolution_status`+`resolution_note`.
- اربط: الضوابط بالمخاطر/الثغرات عبر `REL-MIT`، والتهديدات/المخاطر بالأصول عبر `REL-AFF`، والأدلة بالضوابط عبر `REL-VER`، والإعدادات بالضوابط عبر `REL-IMP`.

## 10. بوابة التحقق قبل النشر
لا يُنشر أي عنصر إلا بعد اجتياز:
- قيم مضبوطة صحيحة لكل الحقول المُقيّدة.
- `sub_domain` ينتمي لـ `primary_domain`.
- الحقول الإلزامية حسب النوع (القسم 5) موجودة.
- توجيه منخفض الثقة للمراجعة، والحفاظ على نسب المصدر الخام (`raw_artifacts.promoted_artifact_id`).

*ملاحظة: القرارات الغامضة أو منخفضة الثقة تُوجَّه دائماً لمراجعة بشرية بدل تخمينها.*
