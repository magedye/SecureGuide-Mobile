# سياسة صياغة موحدة للعناصر والكيانات والضوابط الأمنية (SecureGuide Drafting Policy)

> **الوثيقة الحاكمة الأعلى لبنية القاعدة هي [`SADP_v1.0.md`](SADP_v1.0.md)** (مطابقتها في [`SADP_CONFORMANCE.md`](SADP_CONFORMANCE.md))؛ عند أي تعارض تُقدَّم SADP. من قواعدها المُلزِمة هنا: لا وسوم حرة (التهديد = بُعد `THR-*` مُطبَّع)، وكل تصنيف إلزامي بقيمة (fallback `*-NA/*-UNKNOWN/*-MULTI` بدل NULL).
>
> هذه السياسة **مصدر معياري** لصياغة محتوى العناصر (AGENTS.md، المرجع 5). تُطبَّق بعد تصنيف العنصر وفق [`CLASSIFICATION_POLICY.md`](CLASSIFICATION_POLICY.md)، وتُخزَّن حقولها في `security_artifacts` كما هو موثّق في [`DATA_DICTIONARY.md`](DATA_DICTIONARY.md).
> في الـMVP تعتمد SecureGuide صياغة إنجليزية canonical أولاً. الحقول العربية اختيارية ومؤجلة كطبقة ترجمة/إثراء لاحقة.

## 1. المبدأ الأساسي للصياغة

كل عنصر أمني في SecureGuide يجب أن يصاغ وفق المبدأ التالي:

> **عنصر واحد = فكرة أمنية واحدة، قابلة للتصنيف، قابلة للفهم، وقابلة للتقييم أو الربط.**

لا نخلط في عنصر واحد بين الهدف، والضابط، وطريقة التنفيذ، والدليل. إذا احتجنا ذلك، ننشئ عناصر مرتبطة بعلاقات مثل REL-SAT, REL-IMP, REL-VER.

لا تنشر SecureGuide النصوص الأصلية الكاملة للضوابط داخل الكتالوج النهائي. المصدر الخام يبقى محفوظاً لأغراض النسب والمعالجة، أما العنصر المعتمد فيُعاد صياغته كنص SecureGuide موحد باللغة الإنجليزية مع source lineage واضح.

## 2. الحقول النصية الأساسية للكيان الأمني

لضمان عدم تحول قاعدة البيانات إلى نصوص مبهمة، يجب تقسيم النص إلى حقول هيكلية:

| عمود قاعدة البيانات | الغرض | الطول المقترح |
|---|---|---|
| `canonical_statement` | النص الموحد الرسمي للعنصر (إن وجد) | جملة إلى جملتين |
| `title_en` / `title_ar` | عنوان مختصر وواضح للعرض والفلترة | 4-10 كلمات |
| `definition_short_en` / `definition_short_ar` | تعريف مختصر موحد | 20-35 كلمة |
| `definition_full_en` / `definition_full_ar` | شرح مطول وكامل للصفحات التفصيلية | 80-180 كلمة |
| `objective_en` / `objective_ar` | لماذا يوجد العنصر؟ (الهدف الأمني) | جملة واحدة |
| `applicability_note` | متى وأين ينطبق هذا العنصر؟ | مختصر |
| `implementation_guidance` | إرشاد تطبيقي غير إلزامي لتسهيل الفهم | فقرة قصيرة |
| `verification_method_note` | كيف نتحقق منه؟ (آلية الفحص، نص حر) | مختصر |
| `evidence_required` | الأدلة المتوقعة (أمثلة على ما يثبت التطبيق) | قائمة قصيرة |
| `common_misinterpretations` | توضيح لمنع سوء الفهم الشائع للعنصر | جملة إلى جملتين |
| `classification_rationale` | تبرير سبب التصنيف المعطى للعنصر | جملة واحدة |
| `source_quote` | أثر مقتضب من المصدر عند الحاجة القانونية/التفسيرية فقط | مقتطف قصير، وليس النص الكامل |

**لغة الـMVP:** الحقول الإنجليزية (`title_en`, `definition_short_en`, `definition_full_en`, `objective_en`) هي الحقول الإلزامية للاعتماد. الحقول العربية (`*_ar`) اختيارية ومؤجلة، ولا تمنع اعتماد العنصر إذا كانت فارغة.

**النسب قبل الاقتباس:** المرجعية تتحقق عبر `source_catalog`, `source_version`, `source_section`, `raw_artifact_id`, و`framework_mappings`. لا يصبح `source_quote` بديلاً عن النسب المنظم، ولا يستخدم لنشر النصوص الأصلية الكاملة.

**قاعدة مهمة جدًا:** لا تجعل `definition_full` بديلًا عن الحقول المنظمة. التعريف المطول يشرح، لكن التصنيف والربط والتقييم يجب أن يبقى في أعمدة مستقلة. وطريقة التحقق الحرة (`verification_method_note`) لا تُغني عن جدول `verification_tools` المطبّع عند الحاجة.

## 3. قواعد صياغة العنوان (Title)

العنوان يجب أن يكون اسميًا ومباشرًا، وليس جملة طويلة أو فعلاً غامضاً.

- **أمثلة جيدة:** Enterprise Asset Inventory, Privileged Access Review, Linux SSH Root Login Restriction, Security Awareness Training, Firewall Default Deny Rule.
- **أمثلة ضعيفة:** Ensure that all systems and users are protected properly, Improve security, Access control, General hardening.

## 4. قواعد التعريف المختصر (Short Definition)

يجب أن يتبع التعريف المختصر باللغة الإنجليزية قالباً واضحاً يشرح المطلوب والنطاق والنتيجة الأمنية:

> **This artifact defines [what is required] within [scope] to achieve [security outcome].**

للضوابط التقنية أو التشغيلية:
> **This control reduces [risk] by requiring [security action] for [scope].**

القالب العربي أدناه يستخدم لاحقاً عند تفعيل الترجمة، وليس شرطاً للـMVP:

> **يحدد هذا العنصر [ما المطلوب] ضمن [النطاق] بهدف [النتيجة الأمنية].**
*مثال:* يحدد هذا العنصر متطلبات إنشاء جرد دقيق ومحدث للأصول المؤسسية التي تخزن أو تعالج أو تنقل بيانات المؤسسة.

للضوابط التقنية أو التشغيلية:
> **يحدد هذا الضابط آلية تقليل خطر [الخطر] من خلال [الإجراء الأمني] على [النطاق].**
*مثال:* يحدد هذا الضابط متطلبات تعطيل تسجيل الدخول المباشر بحساب root عبر SSH لتقليل مخاطر الوصول غير المصرح به للأنظمة Linux/Unix.

## 5. قواعد التعريف المطول (Full Definition)

التعريف المطول يجب أن يجيب عن 5 أسئلة:
1. ما هو العنصر؟
2. لماذا هو مهم؟
3. أين ينطبق؟
4. ما الحد الأدنى المتوقع؟
5. كيف يمكن التحقق منه؟

**قالب مقترح:**
> This artifact describes [requirement/control/configuration/procedure] related to [subject]. It supports [security objective] and reduces [risk or gap]. It applies to [scope, systems, or assets]. The minimum expected outcome is [expected behavior or standard]. Verification can be performed through [method] using evidence such as [examples].

**قالب عربي لاحق للترجمة:**
> يصف هذا العنصر [المتطلب/الضابط/الإعداد/الإجراء] المتعلق بـ [الموضوع]. يهدف إلى [الهدف الأمني] وتقليل مخاطر [الخطر أو الفجوة]. ينطبق على [النطاق أو الأنظمة أو الأصول]. يتطلب الحد الأدنى [المعيار أو السلوك المتوقع]. يمكن التحقق من التطبيق من خلال [طريقة التحقق] وأدلة مثل [أمثلة الأدلة].

## 6. قواعد الصياغة حسب النوع (Artifact Type)

تختلف صياغة العنصر باختلاف نوعه في USACM:

| النوع (USACM) | صيغة مناسبة |
|---|---|
| ART-REQ (متطلب) | يجب تحقيق نتيجة أمنية محددة دون فرض طريقة تنفيذ واحدة. |
| ART-CTR (ضابط) | يجب تطبيق إجراء أو آلية تقلل خطرًا أو تحقق التزامًا. |
| ART-CFG (إعداد) | يجب ضبط نظام أو مكوّن بقيمة محددة قابلة للفحص. |
| ART-POL (سياسة) | يجب تعريف واعتماد ونشر قاعدة إدارية أو تنظيمية. |
| ART-PRC (إجراء) | يجب اتباع خطوات تشغيلية محددة. |
| ART-EVD (دليل) | يمثل دليلاً يثبت تطبيق أو تحقق عنصر آخر. |
| ART-MET (مقياس) | يقيس حالة أو فعالية عنصر أمني. |
| ART-RSK (خطر) | يصف سيناريو خطر وأثره واحتماله. |
| ART-AST (أصل) | يصف أصلًا معلوماتيًا أو تقنيًا يحتاج حماية. |

**أمثلة صيغ معيارية:**
- **Requirement:** The organization must maintain an accurate inventory of information and technology assets that store, process, or transmit organizational data.
- **Control:** The organization must periodically review privileged user access to verify alignment with least privilege.
- **Technical configuration:** SSH must be configured to prevent direct root login and disable empty passwords.
- **Evidence:** This artifact represents a report or log proving that privileged access review was performed during a defined assessment period.
- **Metric:** This metric measures the percentage of registered and current assets compared with all known in-scope assets.

أمثلة عربية لاحقة للترجمة:
- **متطلب:** يجب على المؤسسة إنشاء جرد محدث للأصول التقنية والمعلوماتية التي تخزن أو تعالج بيانات المؤسسة.
- **ضابط:** يجب تطبيق مراجعة دورية لصلاحيات المستخدمين ذوي الامتيازات العالية للتأكد من توافقها مع مبدأ أقل صلاحية.
- **إعداد تقني:** يجب ضبط خدمة SSH لمنع تسجيل الدخول المباشر باستخدام حساب root وتعطيل كلمات المرور الفارغة.
- **دليل:** يمثل هذا الدليل تقريرًا أو سجلًا يثبت تنفيذ مراجعة صلاحيات المستخدمين خلال فترة تقييم محددة.
- **مؤشر قياس:** يقيس هذا المؤشر نسبة الأصول المسجلة والمحدثة مقارنة بإجمالي الأصول المعروفة داخل النطاق.

## 7. أفعال موحدة مقترحة للاستخدام

- **للإلزام:** يجب إنشاء، يجب تطبيق، يجب تفعيل، يجب تعطيل، يجب توثيق، يجب مراجعة، يجب مراقبة، يجب تقييد، يجب التحقق من.
- **للتوصية:** يوصى بتطبيق، ينبغي مراجعة، يفضل توثيق.
- **للتعريف:** يحدد هذا العنصر، يصف هذا الضابط، يمثل هذا الدليل، يقيس هذا المؤشر.

## 8. قواعد الجودة العامة للاعتماد

أي صياغة نهائية لعنصر أمني (بعد الـ Normalization) يجب أن تكون:
1. محددة وليست عامة.
2. قابلة للتصنيف حسب USACM و SDT بشكل قاطع.
3. قابلة للربط بمصدر أو معيار بخط واضح (Lineage).
4. قابلة للتقييم أو التحقق كلما أمكن (Testability).
5. لا تحتوي أكثر من مطلب رئيسي واحد لتسهيل التطبيق.
6. خالية من الكلمات الفضفاضة (مثل: مناسب، جيد، كافٍ، قوي، حديث) إلا إذا تم تعريف معيارها.
7. لا تخلط بين "ما يجب تحقيقه" و"كيف يتم تنفيذه" إلا إذا كان النوع ART-CFG أو ART-PRC.
8. مكتوبة بصياغة SecureGuide الأصلية، لا كنسخ حرفي مطول من المصدر.
9. قابلة للتحسين لاحقاً من خلال Curation Workbook دون فقدان `artifact_id` أو النسب.

## الصيغة الذهبية لـ SecureGuide

كل عنصر أمني معتمد يتم تخزينه وعرضه للمستخدم وفق المعادلة التالية:
> **عنوان مختصر + تعريف مختصر + تعريف كامل + نوع USACM + مجال SDT + نطاق تطبيق + طريقة تحقق + أدلة + مصدر + علاقات.**

بهذا تصبح العناصر قابلة للفهم للمستخدم، وقابلة للمعالجة آليًا، وقابلة للتدقيق لاحقًا.
