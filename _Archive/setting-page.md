## 📋 أولاً: الإطار المفاهيمي

### 1.1 فلسفة صفحة الإعدادات

صفحة الإعدادات في SecureGuide ليست مجرد قائمة خيارات، بل هي **"مركز التحكم المؤسسي"** الذي يربط بين:

| البعد | الوظيفة |
|-------|---------|
| **السياق المؤسسي** | تشكيل هوية المؤسسة وتأثيرها على التوصيات |
| **إدارة الملفات** | تبديل الملفات المؤسسية والقوالب |
| **الذكاء الاصطناعي** | ضبط محركات التصنيف والاستخراج |
| **الحوكمة** | التدقيق، المشاركة، الامتثال |
| **البيانات** | التزامن، النسخ الاحتياطي، التصدير |

### 1.2 الموقع في البنية

```
┌─────────────────────────────────────────────────────────────────┐
│  الشاشات الثمانية (8 Screens)                                  │
├─────────────────────────────────────────────────────────────────┤
│  1. Home (لوحة القيادة)                                        │
│  2. Profile Manager (إدارة الملفات)                            │
│  3. Master Catalog (الكتالوج المرجعي)                          │
│  4. Indicators (مؤشرات الاختراق)                               │
│  5. Review Queue (طابور المراجعة)                              │
│  6. Artifact Detail (التفاصيل)                                 │
│  7. Security Info (مركز المعرفة)                               │
│  8. Settings ⭐ (الإعدادات - محور التحكم)                      │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 المحركات المرتبطة

| المحرك | التفاعل مع الإعدادات |
|--------|---------------------|
| **Context Engine** | يقرأ السياق المؤسسي ويؤثر على التوصيات |
| **Classification Engine** | يستخدم عتبات الثقة ونماذج AI |
| **Data Integrity Engine** | يدير التزامن والنسخ الاحتياطي |
| **Audit Engine** | يسجل جميع تغييرات الإعدادات |

## 🎯 سادساً: سيناريوهات الاستخدام

### 6.1 سيناريو 1: مؤسسة مالية جديدة تبدأ استخدام التطبيق

```
1. المستخدم يفتح التطبيق لأول مرة
   ↓
2. يختار قالب "الامتثال المالي (PCI)" من صفحة Profile Manager
   ↓
3. يفتح الإعدادات → السياق المؤسسي
   ↓
4. يملأ:
   - القطاع: مالي
   - الدولة: السعودية
   - اللوائح: NCA ECC, PCI DSS, PDPL
   - حساسية البيانات: عالٍ جداً
   - المستوى المستهدف: MANAGED
   ↓
5. يحفظ التغييرات
   ↓
6. Context Engine يُحدِّث السياق
   ↓
7. Priority Engine يعيد حساب الأولويات (الامتثال المالي = +30%)
   ↓
8. Recommendation Engine يقترح أدوات متوافقة مع PCI DSS
   ↓
9. Progress Engine يحسب النضج بناءً على PCI DSS Requirements
   ↓
10. الصفحة الرئيسية تُحدَّث بالمؤشرات الجديدة
```

### 6.2 سيناريو 2: تغيير عتبات الثقة للذكاء الاصطناعي

```
1. المستخدم يلاحظ أن التصنيفات تلقائياً كثيرة
   ↓
2. يفتح الإعدادات → الذكاء الاصطناعي
   ↓
3. يرفع عتبة القبول التلقائي من 0.90 إلى 0.95
   ↓
4. يخفض عتبة المراجعة البشرية من 0.60 إلى 0.70
   ↓
5. يحفظ التغييرات
   ↓
6. Classification Engine يطبق العتبات الجديدة
   ↓
7. Review Queue يمتلئ بالكيانات التي كانت ستُقبل تلقائياً
   ↓
8. المستخدم يراجع الكيانات الجديدة ويوافق عليها
   ↓
9. Audit Engine يسجل تغيير العتبات والمراجعات
```

### 6.3 سيناريو 3: تبديل الملف النشط قبل التدقيق

```
1. التدقيق المالي قريب (بعد أسبوع)
   ↓
2. المستخدم يفتح الإعدادات → إدارة الملفات
   ↓
3. يفعّل ملف "الامتثال المالي (PCI)" كملف نشط
   ↓
4. Context Engine ينشر PROFILE_SWITCHED Event
   ↓
5. Progress Engine يعيد حساب المؤشرات للملف الجديد
   ↓
6. Home Page تُحدَّث:
   - النضج: 25% (بدلاً من 65%)
   - الفجوات: 30 (بدلاً من 8)
   - الإجراء التالي: يركز على PCI DSS Requirements
   ↓
7. المستخدم يركز على سد الفجوات قبل التدقيق
   ↓
8. بعد التدقيق، يعيد تفعيل "خط الأساس المؤسسي"
```
